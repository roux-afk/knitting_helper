# Петелька 0.2 — локальная мастерская вязания

Настольное приложение на Electron для учета изделий, фотографий, пряжи и времени. Интерфейс — Next.js/React, база — SQLite. Для пользователя не нужны Docker, PostgreSQL или установленный Node.js. Работа после установки не требует интернета.

## Установка и использование

Для Windows x64: [установка и перенос данных](docs/windows.md). Кросс-сборка с Mac — `npm run desktop:windows`, результаты в `dist/windows`. Проверка состава Windows-пакета не заменяет запуск на Windows.

Для macOS собираются приложение `Петелька.app`, DMG и ZIP. Для Windows — установщик EXE. Каждая сборка выпускается для своей ОС и архитектуры; архив мастерской общий для всех платформ.

В меню **Мастерская**:
- **Сохранить мастерскую…** — один JSON-файл со всеми записями и фотографиями.
- **Восстановить мастерскую…** — проверка архива, резервная копия текущих данных и замена мастерской.
- **Открыть папку данных** и **Открыть резервные копии**.

Для переноса на другой компьютер сохраните мастерскую, установите там приложение и восстановите файл. Это перенос состояния, не синхронизация: изменения двух независимых копий не объединяются. При восстановлении активный таймер останавливается на момент создания архива.

Приложение создает одну резервную копию при первом запуске за день и хранит 14 последних дневных копий и по одной в неделю за 8 недель; копии перед восстановлением, обновлением и миграцией — по 5 последних каждого вида. Копия перед восстановлением включает фотографии. Копия перед миграцией схемы содержит SQLite-базу; фотографии остаются в прежней папке. Для защиты от поломки диска сохраняйте переносимый архив на другой носитель.

## Обновления

**Настройки → Обновления** или **Мастерская → Проверить обновления…** ищет новую версию в GitHub Releases, скачивает ее и устанавливает с перезапуском, предварительно сохранив резервную копию. Работает в установленной версии для Windows. Как выпускать версии — [docs/releasing.md](docs/releasing.md).

## Хранение

- macOS: `~/Library/Application Support/Петелька/`.
- Windows: `%APPDATA%/Петелька/`.
- `workshop.sqlite` — база; `photos/` — фотографии; `backups/` — копии; `desktop.log` — журнал текущего запуска.

Данные находятся отдельно от программы и не включаются в установщик. Не копируйте работающую SQLite-базу вручную: используйте экспорт. В базе вес хранится целым числом миллиграммов, длина — миллиметров, деньги — копеек. API и интерфейс используют граммы, метры и рубли.

Один экземпляр приложения запускает сервер на случайном порту только на `127.0.0.1`. Запросы защищены временным токеном; окно изолировано от Node.js. PostgreSQL не используется в повседневной работе.

## Разработка

Нужен Node.js 24.13+ или 26. Зависимости зафиксированы в `package-lock.json`.

```sh
npm ci
npm test
npm run typecheck
npm run desktop:prepare
npm run desktop:verify
npm run desktop:start
```

`npm run desktop:pack` собирает папку с приложением, `npm run desktop:dist` — установочный пакет для текущей платформы. Для Windows x64 также поддерживается отдельная кросс-сборка с заменой нативного модуля фото. После изменений серверной части повторите `desktop:prepare`.

Для веб-разработки: `npm run dev`, адрес http://127.0.0.1:4317. Здесь по умолчанию отдельные данные `data/local/`; путь задается `KNITTING_DATA_DIR`. Схема SQLite обновляется автоматически при первом обращении. Режим разработки не должен одновременно работать с той же базой, что и Electron.

Выпуск по тегу `v*` выполняет `.github/workflows/release.yml` на Windows. Сценарий `.github/workflows/desktop.yml` готовит пробные сборки на Windows x64, Mac Intel и Mac Apple Silicon. Он запускается вручную после размещения проекта в GitHub; из локального проекта ничего автоматически не публикуется. Подпись и нотариальное заверение выпусков пока не настроены. Сборку Windows необходимо отдельно проверить на Windows.

## Перенос прежней PostgreSQL-мастерской

Старая база и скрипты сохранены для перехода. `npm run db:import-postgres` читает старую базу, сохраняет исходный JSON-архив и переносит записи в пустую SQLite-мастерскую. Цель задается `KNITTING_DATA_DIR`, источник — `DATABASE_URL` или прежний локальный сокет. Команда отказывается перезаписывать непустую мастерскую. Выполняйте ее при закрытом приложении. Старые `db:start`, `db:stop`, `db:migrate` относятся только к PostgreSQL.

## Импорт Excel и учет

Предпросмотр исходной книги распознает 26 шаблонов, 38 записей изготовлений (60 вещей) и 47 покупок. Формулы не выполняются; используются сохраненные результаты с замечаниями. Исторические изделия не списывают запас, покупки из Excel сохраняются как история. Текущие остатки нужно взвесить и внести поступлением. Продажи и боковые заметки не переносятся.

Обычный расход списывается при сохранении, исправление меняет запас на разницу, завершение не списывает повторно. Стоимость рассчитывается по FIFO. Неизвестная цена отличается от нулевой. Одновременно работает один таймер.

## Проверки и дальнейшие этапы

`npm test` проверяет учет, конкурентные команды, точность, импорт, экспорт с фото, восстановление и отказ при поврежденном архиве. Используются временные SQLite-базы; PostgreSQL не нужен.

`desktop:verify` проверяет production-сервер в отдельной временной папке, чтобы отсутствующие зависимости не подгружались из проекта. Эта же проверка выполняется после упаковки перед созданием установщика: интерфейс и статические файлы, защита API, учет, фото, архив и Excel-импорт.

Пока нет синхронизации между компьютерами, учета продаж и резервирования пряжи. Локальная версия рассчитана на одну мастерскую.

Ранние документы `docs/architecture.md` и `docs/data-model.md` описывают первоначальный вариант PostgreSQL/Supabase. Актуальное решение для локальной версии — [desktop.md](docs/desktop.md).
