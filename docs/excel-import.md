# Разбор Excel и план переноса

Источник: книга `Вязание.xlsx`, лист `2026`. Файл изучен только для чтения. Структура, формулы и сохраненные результаты рассмотрены отдельно; пересчет Excel не выполнялся. Ниже указаны особенности данных, а не инструкции из документа.

## Структура

| Область листа | Содержимое | Будущая сущность |
| --- | --- | --- |
| A2:K28 | Заголовок и 26 вариантов товаров | Шаблоны, плановые материалы, нормативное время и цена |
| A33:H88 | Покупки пряжи, 47 строк поступлений и итоги | Продукты, цвета, исторические поступления |
| A92:E112 | Продажи, 17 строк и итоги | Позднее — продажи; пока оставить в источнике |
| A116:L165 | Выполненные изделия: 38 строк изготовления и итоги | Завершенные проекты, в том числе партии |
| O115:R128 | Свободные заметки о будущих изделиях | Не импортировать автоматически; позднее — планы после ручного разбора |

Выполненные изделия содержат 60 штук при прямом суммировании количества в строках проектов. Сохраненный годовой итог показывает 56: формула промежуточного итога пропускает часть строк. Это контроль импорта, а не основание менять исходный файл. Встроенных фотографий не обнаружено.

## Сопоставление полей

### Варианты товаров: строки 3–28

| Столбец | Поле приложения |
| --- | --- |
| A — название | template.name |
| B — пряжа | template_materials, иногда несколько строк |
| C — расход | плановые граммы на одну штуку |
| D — часы | planned_seconds_per_unit = часы × 3600 |
| E — вес мотка | характеристика/снимок для оценки |
| F — стоимость мотка | плановая цена, не фактическая цена покупки |
| G — другие материалы | плановая дополнительная стоимость |
| H — материалы | исходный расчет для сверки |
| I — работа | ставка и исходный расчет; ставка в формулах зашита как 125 руб./ч |
| J — общая стоимость | исходный итог для сравнения |
| K — назначенная цена | suggested_unit_price |

Поле шаблона `planned_other_material_cost` покрывает столбец G без обязательной детализации фурнитуры.

### Покупки: строки 34–86 без итогов

Дата, название, личный номер, граммы и метры на моток, цвет, число мотков, стоимость строки покупки. Общий вес = граммы на моток × число мотков; цена грамма = сумма покупки / общий вес. Производитель, линейка и состав могут потребовать ручного дополнения: не извлекать их догадкой из названия без подтверждения.

### Выполненные изделия: строки 119–163 без заголовков и итогов

Название → title; количество → quantity; дата → end_date с точностью; пряжа/номер → материалы; расход на штуку → общий расход × quantity; дополнительные материалы → expenses/заметки; стоимость на штуку → исторический снимок; часы на штуку → ручная длительность × quantity; назначение → purpose.

Дата начала отсутствует — оставить неизвестной. Имена изделий, полученные формулой-ссылкой, брать из сохраненного значения с проверкой источника. Каждая строка становится одним проектом-партией, не шаблоном и не набором фиктивных сеансов.

## Неоднозначности и ошибки для предварительного просмотра

1. **Личные номера стали датами.** C34:C86 содержит даты с форматом `d.m`; это коды позиций, а не даты покупки. Предлагать строковый код из отображаемых дня/месяца и сохранять происхождение. В выполненных изделиях номера встречаются как `61`, `6.1` и списки. Автосопоставление возможно только при однозначном совпадении пряжи и цвета; иначе нужен выбор.
2. **Количество мотков записано выражением.** Например, G34:G35 содержит текст вида `1*5`, `2*5`. Поддержать только ограниченную грамматику произведения положительных чисел. Не использовать eval и не выполнять произвольный код или макросы.
3. **Несколько материалов в одной ячейке.** B15:F15 и строки 148–149 требуют разбиения на материалы с соответствующими весами и ценами. Запятая может быть разделителем списка или десятичным знаком; учитывать структуру строки, неоднозначные значения не угадывать.
4. **Нет расхода по каждому цвету.** Например, E129:F131 перечисляют цвета, но дают один общий вес. Не распределять его поровну. Сохранить известный общий расход исторически, привязку к остаткам оставить незавершенной.
5. **Неизвестный расход.** F119:F120, F153 и данные материалов в D163:F163 неполны. Пустое поле не превращать в нулевое потребление.
6. **Даты различной точности.** C120 — точная дата, другие строки имеют `05.26`, `06.26` и т. п. Не выдумывать день месяца.
7. **Цена с пояснением.** H75:H77 содержит ноль и текст о покупке другим человеком. Сохранить примечание, различать личные денежные затраты и оценку стоимости полученной пряжи. Для оценки себестоимости требуется явный выбор: нулевая либо неизвестная стоимость; не приписывать цену из другой покупки.
8. **Разные названия и характеристики.** Встречаются варианты написания названий. В E15 вес джута в составном поле отличается от D71; это вопрос сверки, не автоматического исправления. Метраж MAXI в E75 также требует проверки против других поступлений этой линейки, без обращения к догадкам.
9. **Потенциально неверные ссылки.** H150 и D104/E104 относятся к ободку, но ссылаются на строку 20 с другой моделью. H143:H145 подставляют полную стоимость из J вместо материалов из H. Показывать исходный результат и предлагаемое сопоставление раздельно.
10. **Неполный итог количества.** B164 суммирует B148:B159 и пропускает B160:B163; B165 использует этот итог. Новые отчеты суммируют записи проектов, а не импортируют итоговые формулы.
11. **Плановые и закупочные цены различаются.** Стоимость в вариантах товаров не обязана совпадать с конкретными покупками. Сохранять исторический расчет как отдельный источник, не пересчитывать молча.

## Рекомендуемый режим перехода

Поскольку таблица не дает полного распределения расхода по цветам, надежнее начинать с текущей инвентаризации:

1. Импортировать варианты товаров как шаблоны.
2. Импортировать выполненные изделия с `accounting_mode=historical`, длительностями и историческими стоимостями; текущие остатки не менять.
3. По покупкам подготовить справочник пряжи и цветов. Историю покупок сохранить в подготовленных данных импорта. Не создавать на ее основе активные складские поступления в этом режиме.
4. Ввести фактически имеющиеся остатки на дату перехода. Создать только `opening`-поступления и движения. Оценку стоимости оставшегося грамма задать явно либо оставить неизвестной.
5. Новые покупки и расход после даты перехода отражать обычными движениями.

Альтернатива — восстановить всю историю покупок и списаний. Для этого необходимо уточнить цветовые распределения и пропуски, затем сверить результат с реальным запасом. Этот режим нельзя сочетать с начальным остатком за тот же период: получится двойной приход.

## Процесс импорта

`Файл → распознавание разделов → подготовленные записи → просмотр проблем → сопоставление → применение → отчет`.

Формулы файла не исполняются на сервере как код. Использовать сохраненные значения, прямые ссылки и ограниченный набор арифметики только при явной поддержке; отсутствие кэша/неподдержанная формула становятся проблемой импорта. При расхождениях сохраненного итога и собственного расчета ничего не заменять без видимого решения.

Hash файла, лист, диапазон и тип записи образуют ключ происхождения. Повторное применение той же операции не создает дубликаты. Измененный файл требует сопоставления с ранее импортированными записями. Строки итогов и боковые заметки исключаются по структуре, а не только по наличию чисел.

Применять согласованный набор небольшой книги одной транзакцией. Нерешенные строки можно явно исключить, перечислив их в отчете; нельзя молча пропустить их. Обратный импорт допустим только до появления зависимых новых операций; после этого — корректирующие движения и архивирование.

## Проверки результата

- 26 исходных шаблонов, 47 строк покупок, 38 строк выполненных изделий; любое исключение объяснено.
- Сумма quantity по всем строкам выполненных изделий — 60; это число вещей, а не проектов.
- Количество/цены покупок с выражениями нормализованы отдельно от итоговых строк.
- Часы на штуку умножены на размер партии ровно один раз.
- Расход нескольких цветов не выдуман; неизвестные значения отмечены.
- Исторические изделия в режиме текущей инвентаризации не создают расход в журнале.
- Повторный импорт не меняет количества записей и остатки.
- Данные о покупателях не попадают в публичные демоданные или тестовые фикстуры.
