# Этапы реализации

> Статус на 30 сентября 2026: локальное приложение перенесено на Electron + SQLite, реализованы проекты, пряжа, время, фото, Excel-импорт и восстановление мастерской. Проходят 21 тест и проверка production-пакета в изолированной папке. Ниже сохранен исходный план веб-версии; актуальный запуск — в README, архитектура — в [desktop.md](desktop.md). Windows-пакет и подпись выпусков требуют отдельной проверки/настройки.

## 1. Основа приложения

Создать Next.js-проект, настроить TypeScript, вход, миграции PostgreSQL, политики владельца, приватные фото и базовую навигацию. Зафиксировать версии и lockfile. Первые данные — вымышленные; рабочая таблица не используется как публичная демонстрация.

Приемка: вход с телефона и компьютера; второй тестовый пользователь не читает чужой проект или фото; восстановление приватного доступа после обновления страницы.

## 2. Банк пряжи

Продукт, цвет, поступление, начальный остаток, покупка, журнал движений, поиск и фильтры. Ввести граммы, пересчет в метры и эквивалент мотков, стоимость поступления.

Приемка: две покупки одного цвета по разной цене хранятся отдельно; добавление частичного мотка работает; повтор запроса не удваивает приход; корректировка создает запись с причиной.

## 3. Проекты и расход

Шаблоны, проекты и партии, статусы, каталог завершенных изделий, несколько материалов, фото и заметки. Транзакционное распределение расхода, возврат и исправление.

Приемка: полный сценарий «купить → начать → списать → исправить → завершить → повторить» без двойных движений. Закрытие/архивирование проекта не меняет уже списанный расход.

## 4. Время и стоимость

Таймер, ручные сеансы, даты, ставка, дополнительные материалы, назначенная цена и версии расчетов.

Приемка: таймер восстанавливается после закрытия браузера; два устройства не запускают два таймера; ручные записи и партии не удваивают часы; новая покупка не меняет себестоимость прежнего проекта.

## 5. Перенос таблицы и личный запуск

Предварительный просмотр импорта, исправление сопоставлений, исторические проекты, ввод реального текущего остатка. Экспорт и восстановление базы вместе с фотографиями. Затем публикация в выбранном окружении.

Приемка: исходные строки сопоставлены с отчетом о пропусках; количество изделий сверено; старые изделия не списали сегодняшнюю пряжу; резервная копия восстановлена в чистом окружении.

## 6. Дополнения после использования

Резервы, продажи, статистика, схемы, счетчики рядов, установка на главный экран и отдельный проект офлайн-синхронизации. Приоритет уточняется по реальному использованию первой версии.

## Критические сценарии тестирования

| Сценарий | Ожидаемое поведение |
| --- | --- |
| 500 г, расход 80 г, исправление на 95 г | Остатки 420 и 405 г |
| Повтор сохранения с тем же ключом | Никаких новых движений |
| Повтор ключа с другим телом | Ошибка конфликта |
| Два одновременных расхода по 80 г из 100 г | Один проходит, другой получает дефицит; отрицательного остатка нет |
| Сохранение двух материалов, второго недостаточно | Полный откат операции |
| Исправить расход с 95 до 80 г | Возврат 15 г на исходное поступление по исходной цене |
| Завершить и снова открыть проект | Сохраненные списания не повторяются и не отменяются |
| Повторить завершенное изделие | Новый проект с планом, без фактических часов и расхода |
| Партия из трех вещей, по 20 г и 2 ч на штуку | Общие итоги 60 г и 6 ч; один сеанс 1 ч добавляет только 1 ч на партию |
| Покупка 100 г за 200 руб. и 100 г за 300 руб.; расход 150 г FIFO | Стоимость расхода 350 руб.; остаток 50 г второго поступления |
| Изменить цену новой покупки/ставку в настройках | Старые снимки стоимости не меняются |
| Одновременный запуск таймера на двух устройствах | Один активный сеанс |
| Завершить проект во время работы таймера | Сеанс закрыт, часы включены один раз |
| Сеть пропала перед ответом на stop | Повтор stop с тем же ключом возвращает прежний результат |
| Историческое изделие с неизвестным расходом | Отмечено неполным, остаток не меняется |
| Повторный импорт | Нет дубликатов проектов и поступлений |
| Чужой UUID проекта/поступления в запросе | Отказ и отсутствие изменений |

Проверки запускаются на уровне, где находится правило: формулы — модульно; гонки, доступ и откат — в PostgreSQL; сценарии пользователя — в браузере. На этапе архитектуры эти тесты описаны, но не реализованы и не запускались.

## Решения перед публикацией

Пока приняты рабочие допущения: личный аккаунт, онлайн-режим, русский язык и RUB. Перед публикацией выбрать хостинг/регион и способ входа; перед реальным импортом решить спорные сопоставления из отчета. Эти решения не мешают начать реализацию основных модулей.
