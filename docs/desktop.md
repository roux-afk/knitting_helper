# Локальная архитектура, 30 сентября 2026

Electron управляет жизненным циклом одного окна и отдельного Node utility process с production-сборкой Next.js. Next обслуживает существующий интерфейс и API. В окне выключен Node.js, включены sandbox и contextIsolation, запрещены внешние переходы, новые окна, webview и разрешения устройств. Доступ к API требует одноразового токена запуска, который Electron добавляет только к запросам собственного origin.

SQLite использует встроенный node:sqlite без отдельного сервера или нативной зависимости SQLite из npm. Команды сериализуются через очередь соединений и BEGIN IMMEDIATE, чтение состояния выполняется в транзакции. SQL-схема лежит в db/sqlite. Физические числовые колонки содержат целые минимальные единицы; функции mg/cents кодируют параметры, decodeRow переводит результаты в единицы интерфейса. Расчет стоимости пропорционального расхода выполняется Decimal, без округления каждой отдельной операции.

Таблица schema_migrations определяет примененные миграции. Перед изменением схемы создается согласованный снимок SQLite. Старая программа отказывается открывать базу с неизвестными миграциями. Журнал движений защищен триггерами от изменения и удаления.

Экспорт JSON версии 1 хранит значения в единицах API, UUID и фотографии в base64. Перед восстановлением архив проверяется во временной базе с текущей схемой, ограничениями и внешними ключами. Затем внутри транзакции создается резервный архив, фотографии записываются под новыми именами, данные заменяются. При ошибке транзакция откатывается, новые фотографии удаляются. Старые фото сохраняются, чтобы ошибка не уничтожила исходники; автоматическая очистка не реализована. Импорт архива не исполняет SQL или пути из файла.

Нативное меню предлагает экспорт/восстановление и открытие папок данных. Предельный размер восстанавливаемого JSON — 200 МБ. Ежедневная копия создается при запуске; автоматической ротации копий пока нет. Копии на одном диске защищают от ошибочных действий, но не от отказа диска.

Сборка: Next standalone + статические файлы + миграции + Electron. Личные данные, исходные XLSX и резервные копии не должны попадать в пакет. Нативный sharp должен соответствовать целевой ОС/архитектуре; отдельный сценарий Windows x64 заменяет его официальным Windows-бинарником с проверкой контрольной суммы. Workflow настроен на macos-15 (ARM), macos-15-intel и windows-2025 (x64); локальный запуск workflow не выполняет публикацию. Подпись релизов и обновления — отдельный этап.
