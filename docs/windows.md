# Петелька для Windows x64

## Установка и перенос мастерской

1. Скопируйте `Petelka-0.2.0-windows-x64-setup.exe` на Windows-компьютер и запустите установщик.
2. Откройте «Петельку» через ярлык. Docker, Node.js и PostgreSQL устанавливать не нужно.
3. На Mac выберите меню **Мастерская → Сохранить мастерскую…** и перенесите полученный JSON на Windows.
4. В Windows выберите **Мастерская → Восстановить мастерскую…**. Архив содержит записи и фотографии. До восстановления приложение сохраняет предыдущую мастерскую.

Альтернатива установщику — ZIP: распакуйте всю папку и запустите `Петелька.exe`. Остальные файлы рядом с EXE обязательны. Данные хранятся в `%APPDATA%\Петелька`, поэтому ZIP не является мастерской, которую можно переносить вместе с записями: для данных используйте экспорт.

Версия рассчитана на Windows x64, не на старые 32-битные системы. Текущий выпуск не подписан цифровым сертификатом издателя. Windows может показать предупреждение о неизвестном издателе.

## Проверка на Windows

Первый запуск готового пакета на Windows еще нужно подтвердить. Проверить: открытие окна, создание проекта, фото, таймер, списание пряжи, сохранение/восстановление архива, повторный запуск с сохраненными данными. Журнал `desktop.log` находится в папке данных; открыть ее можно из меню «Мастерская».

## Сборка

`npm run desktop:windows` собирает production-интерфейс и проверяет API в изолированной папке, готовит отдельный `desktop-win`, загружает Windows-модуль sharp строго указанной версии и проверяет SHA-512 по `package-lock.json`. Затем electron-builder создает NSIS-установщик и ZIP в `dist/windows`.

Кросс-сборка на Mac заменяет только нативные библиотеки обработки фото; SQLite входит в Windows-версию Electron. Проверка пакета подтверждает наличие зависимостей и PE x64-формат EXE, NODE и DLL, запрещает случайное включение macOS/Linux-библиотек. Это проверка состава, а не запуск приложения в Windows. Отчет сохраняется в `win-unpacked/build-verification.json`.

Полная проверка runtime на Windows предусмотрена в `.github/workflows/desktop.yml`: используется Windows runner, тесты учета, production API и проверка уже упакованного сервера. Workflow пока не запускался удаленно.
